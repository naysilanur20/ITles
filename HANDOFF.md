# ИТлес — передача текущей версии

Дата: 2026-09-16. Это продолжение от `4a236b2a158beb09d21387eb9dc7864a3c2d8230`.
Точный проверенный commit и SHA-256 набора исходников — в
`docs/verification-results.json`. Старые отчёты и каталоги `published/` являются
историей; их успешные результаты не подтверждают новый checkout.

## Что реализовано

- Три веб-пути: создание отдельной компании и администратора, индивидуальный
  вход/активация сотрудников, изолированный вымышленный учебный парк.
- Сохраняемая настройка компании: машина, доступ, описание источника,
  ограниченный токен устройства, получение сообщения и отдельная сверка.
- Серверные роли и изоляция организаций, отзыв доступа/токенов, завершение
  сеансов, PBKDF2, ограничение попыток, одноразовое восстановление администратора.
  Пользователь читает весь парк своей компании; отдельных разрешений по машинам нет.
- Версионированная миграция сохраняет прежние организации и данные. Старый
  общий пароль даёт только переходное чтение, не административные права.
- Нормализованный JSON API, outbox с повторной доставкой и дедупликацией,
  последние показания/координаты, выработка по раздельным базам и CSV-журнал.

## Что исправлено в этом продолжении

1. Служебные код компании и UUID событий демо нельзя занять регистрацией или
   ingest до первого запуска сценария. Уже существующий конфликт возвращает
   503 JSON, не удаляя данные. Это не установленный диагноз внешнего отказа пользователя.
2. Проверка поступления сохраняет несохранённый черновик источника; устаревший
   ответ не позволяет выдать токен или подтвердить сверку как по свежим сведениям.
3. Переход «Открыть показания машины» заново загружает данные после ingest,
   в том числе если машина уже была выбрана. Регрессия проверяет реальный HTTP и `0%`.
4. Замена кода сотрудника требует подтверждения отмены прежнего пароля и сессий.
   Отзыв переходного legacy-доступа доступен в UI. Каждый новый секрет требует
   нового подтверждения сохранения.
5. В парке поиск и фильтр состояния заменяют повторный список проблем.
   Входные тексты сокращены, палитра и компоновка обновлены. Сведения об ошибке
   включают UTC-время, endpoint, статус, request ID и сборку интерфейса без секретов.
6. Браузерные регрессии воспроизводимы и включены в CI; холодный перезапуск и
   восстановление SQLite проверяются отдельным тестом в новых Python-процессах.
   Архивы теперь содержат HANDOFF и browser e2e.

## Как продолжать и проверять

```sh
bash .hoplite/setup.sh
.venv/bin/python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
.venv/bin/python -m scripts.stress_synthetic --records 10000
cd frontend && npx playwright install chromium && cd ..
npm --prefix frontend run test:e2e
```

По умолчанию E2E владеет временной БД и отдельным loopback-сервером на 3100;
по завершении БД удаляется. Не направлять тесты на сервер заказчика.
Опциональный `ITLES_E2E_BASE_URL` допускает только частный loopback-стенд;
на нём остаются вымышленные компании, а выданные тестами доступы отзываются.
Снимки, trace и видео тестов отключены: формы показывают одноразовые секреты.

Preview запускается репозиторным `.hoplite/run.sh`: полный FastAPI + собранный
frontend, отдельная `.local/itles.sqlite3`, demo включён, Secure-cookie включены
по умолчанию для HTTPS Preview. Только частный локальный HTTP-стенд запускается
с явным `ITLES_COOKIE_SECURE=0`; это не настройка публичного Preview или production.
В production — HTTPS,
`ITLES_COOKIE_SECURE=1`, постоянный том и проверенная резервная копия.

Инструкции: `docs/administrator.md`, `docs/user-guide.md`, `docs/deployment.md`,
`docs/api-contract-v2.md`. Дизайн и ограничения карты: `DESIGN.md`.
Исходный аудит этого продолжения: `docs/baseline-current-2026-09-16.md`.

## Уровни доказательств

- Автоматически: Python, frontend, сборка, миграции, роли, восстановление,
  целостность документов и архивов. Точные результаты — в журнале проверки.
- Синтетически в реальном Chromium: регистрация/вход/выход, сохранение настройки,
  доступ сотрудников, чужие ID/API/CSV, source/token/ingest/review, демо/карта/периоды,
  ошибки, мобильные ширины и клавиатура. Это не испытание физической машины.
- Синтетически в отдельных процессах: холодный старт приложения, сохранение
  аккаунта/сессии/телеметрии, backup/restore и точный CSV. Это не TCP/TLS и не Docker.
- Docker CI — отдельная проверка сборки и контейнера; её актуальный результат
  брать из GitHub для конкретного SHA, не из прежнего отчёта.
- На реальном OEM-файле, реальной машине, конфигурации 1С заказчика — не проверено.

## Что остаётся ограничением

- 16.09.2026 получен HTTPS-адрес Preview и `session_not_retained` в 12:59:04.835 UTC.
  Воспроизведён отказ сеанса в iframe другого сайта: POST 200, затем `/me` 401.
  Встроенный экран теперь предлагает новую вкладку до входа/регистрации;
  ключ для демо не нужен. В отдельной вкладке проверены вход, reload и выход.
  Внешний шлюз требует авторизации Hoplite в агентском браузере; его сквозной
  результат не подтверждён. Не выдавать локальную регрессию за проверку адреса
  пользователя и не считать старый nginx/405 причиной этого инцидента.
- Универсального OEM/CAN/StanForD-адаптера нет. Для конкретной машины нужны модель,
  компьютер, версия ПО, разрешённый интерфейс и обезличенный эталонный экспорт;
  следующий этап — отдельный адаптер и проверка по источнику.
- Принятый пакет и ручная сверка не подтверждают точность датчиков. Ноль отличается
  от отсутствия, базы объёма не объединяются, происхождение и версии сохраняются.
- SQLite и ограничения попыток рассчитаны на один процесс сервиса. Масштабирование
  требует отдельной инженерной работы; не запускать много независимых workers.
- Восстановление без действующего одноразового кода требует отдельного подтверждения
  прав владельцем сервера. Email/SMS и автоматический захват по названию не добавлены.
- Внешние HTTPS, production-хостинг, резервное копирование заказчика и реальная
  техника в этой песочнице не проверены и не изменялись.
