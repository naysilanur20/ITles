# ИТлес

Первая проверяемая версия мониторинга харвестеров: веб-регистрация компаний,
личные доступы с ролями, настройка источников, локальная очередь доставки,
API, SQLite, карта парка, карточки машин и реестр объёма.
**OEM/CAN/StanForD-адаптер и реальная 1С не подключены.** Учебный парк вымышленный,
без имитации движения. Число знаков после запятой не означает точность измерения.

## Локальный запуск учебного стенда

Нужны Python 3.12, Node.js 22 с npm и шрифты DejaVu Sans
(в Debian/Ubuntu: пакет `fonts-dejavu-core`).

```sh
bash .hoplite/setup.sh
ITLES_COOKIE_SECURE=0 bash .hoplite/run.sh
```

Откройте `http://localhost:3000` и выберите «Посмотреть демо».
Команда выше предназначена **только для частного локального HTTP-стенда**:
исключение `ITLES_COOKIE_SECURE=0` задано явно. Сам `.hoplite/run.sh` по умолчанию
включает учебные данные и защищённые Secure-cookie для HTTPS Preview.
В публичном Preview запускайте его без этого исключения, открывайте отдельную
вкладку и нажимайте «Посмотреть демо» — ключ не нужен. Настройки приложения
без run-скрипта: demo выключен, Secure-cookie включены. База создаётся в `.local/`;
она, ключи и окружение не входят в Git или архив исходников.

```sh
.venv/bin/python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
.venv/bin/python scripts/build_deliverables.py
.venv/bin/python -m scripts.stress_synthetic --records 10000
```

Браузерные регрессии запускаются отдельно командой
`npm --prefix frontend run test:e2e`. Нужен Chromium для зафиксированной версии
Playwright; установка и правила изоляции описаны в
[инструкции тестов](frontend/e2e/README.md). По умолчанию используется временная
БД, а не база работающего Preview. Артефакты ошибок могут содержать тестовые
коды доступа — не публикуйте их без очистки.

Документы создаются в `deliverables/`: Excel с источниками, отчёт DOCX/PDF,
Markdown и ZIP исходников. Их можно скачать из раздела «Документы».
Исходная пользовательская книга `harvesters_rf.xlsx` не перераспространяется;
её утверждения рассмотрены отдельно и не приняты за проверенные факты.

## Создать компанию и подключить сотрудников

Обычная регистрация и настройка не требуют CLI или доступа к серверу:

1. **«Я администратор компании»**: создать отдельную компанию, задать личный
   пароль, сохранить одноразово показанный код восстановления.
2. **«Компания»**: добавить машину, выдать сотрудникам личные коды активации,
   сохранить обследование источника. Можно продолжить после выхода или перезагрузки.
3. **«Войти в компанию»**: сотрудник активирует выданный доступ и задаёт свой
   пароль. В дальнейшем входят по коду компании, служебному логину и паролю.
4. **«Посмотреть демо»**: изолированный учебный парк без регистрации,
   редактирования компаний и выдачи токенов устройств.

Роли проверяются сервером для API и CSV. Обычный пользователь читает весь парк
своей компании; администратор управляет машинами, источниками и доступами.
Права по отдельным машинам и назначение второго администратора через веб пока
не реализованы. Старые общие аккаунты мигрируют без автоматического повышения
привилегий; порядок подтверждения владельца описан в инструкции администратора.

- [Администратору компании](docs/administrator.md): регистрация, доступы,
  восстановление, первая передача и состояния источника.
- [Пользователю и руководителю](docs/user-guide.md): парк, время данных,
  выработка, CSV, ошибки и выход.
- [Контракт API и права](docs/api-contract-v2.md).

## Передать нормализованные события

Не используйте внешний Preview для реальных координат или файлов предприятия.
Сначала согласуйте размещение и правила обработки данных: [privacy](docs/privacy.md).
В «Компания → Машины и подключение» выберите машину и сохраните поддерживаемый
источник JSON с разрешением на чтение. Выдайте токен после подтверждения личного
пароля. Он показывается один раз и ограничен этой машиной. Новый токен отменяет
старые; смена на неподдерживаемый источник или снятие разрешения также отменяет
его токены. Не сохраняйте секрет в Git, скриншоте, отчёте или общем журнале.

Контракт: [`backend/schemas.py`](backend/schemas.py), OpenAPI `/openapi.json`.
Приём — `POST /api/ingest` с `Authorization: Bearer …`; ключ ограничен одной
машиной. Команды отправки и точный ID доступны в настройке источника машины;
общее объяснение — в разделе «Инструкция».
Это не сырой HPR: выделение разрешённых полей и стабильных ID выполняется
локальным адаптером на стороне предприятия. Поле `method_version` обязательно;
`unknown` допустимо, но не подтверждает физическую точность объёма.

```sh
.venv/bin/python -m edge.outbox --db .local/outbox.sqlite3 enqueue normalized.json
# ITLES_DEVICE_TOKEN передаётся через защищённое окружение, не параметр команды.
.venv/bin/python -m edge.outbox --db .local/outbox.sqlite3 flush --url https://your-approved-host.example
.venv/bin/python -m edge.outbox --db .local/outbox.sqlite3 status
```

Сервер не исправляет конфликтующие записи молча. Источник должен сохранять
идентичность события при повторной выгрузке; новый ID каждый раз приведёт
к двойному учёту. При накопительных snapshots нужен отдельный адаптер.

## Развёртывание вне Preview

Для контейнерного хостинга используйте корневой `Dockerfile` и архив
`itles_deploy.zip`, а **не статический шаблон React/Vite**. Он собирает интерфейс
и запускает Python API на одном порту 8080. Постоянный диск — `/data`.
Настройки Deploy-F, обслуживание БД, миграция и диагностика 405:
[инструкция размещения](docs/deployment.md).

Текущая архитектура — один процесс и постоянный локальный диск. Не загружайте
её как обычную бессерверную функцию Vercel: файловая система функции не заменяет
постоянную БД. Нужен согласованный сервер/контейнер с диском, TLS-прокси,
резервным копированием и проверкой восстановления. Пример команды за TLS-прокси:

```sh
ITLES_DB_PATH=/srv/itles-data/itles.sqlite3 ITLES_DEMO_ENABLED=0 ITLES_COOKIE_SECURE=1 \
  .venv/bin/python -m uvicorn server:app --host 127.0.0.1 --port 3000 --workers 1 --no-access-log
```

Путь `/srv/itles-data` — пример отдельного постоянного каталога: заранее создайте
его с доступом только для служебного пользователя. Не используйте учебную
`.local/itles.sqlite3` как рабочую базу. Настройки передаются окружением процесса;
само создание `.env` не настраивает Python-сервер.

До реальных данных обязательны: проверка авторизации, ротация/отзыв ключей,
согласование минимальных ролей, аудит действий при необходимости, сроки хранения и удаление,
защита диска/резервных копий, лимиты на уровне прокси, нагрузочный тест
и юридическая проверка размещения. Текущий лимитер входа локален одному процессу.
Это не завершённая промышленная система безопасности и не SLA.
