# Изолированные браузерные регрессии

Установка: `npm --prefix frontend ci`, затем `cd frontend && npx playwright install chromium`.
На минимальном Linux образе системные библиотеки устанавливаются командой
`npx playwright install --with-deps chromium` после проверки разрешений окружения.

Обычный запуск из корня: `npm --prefix frontend run test:e2e`.
Playwright сам собирает frontend и запускает полный FastAPI на `127.0.0.1:3100`
с новой временной SQLite. База удаляется после остановки. Существующий процесс
на этом порту не переиспользуется. Требуется `.venv` после `.hoplite/setup.sh`.
Остановка по SIGTERM/SIGINT штатная; при принудительном SIGKILL временная папка
может остаться в системном `/tmp`. Это не рабочая база.

В `.github/workflows/verify.yml` Chromium устанавливается из зафиксированной
версии Playwright, затем выполняется этот же изолированный запуск. Ошибки
останавливают CI; ретраи и пропуски не включены. Браузерные артефакты не
загружаются в GitHub, поскольку диагностика может содержать одноразовые коды.

Выход проверяется после ответа POST `/api/auth/logout` и возврата экрана входа:
окончание клика не означает завершение запроса. Исходная cookie повторно
отправляется в API, где ожидается 401 — одного удаления cookie недостаточно.
Сценарий регистрации удерживает запрос выхода до проверки состояния ожидания,
затем отправляет его реальному серверу. Ответ не подменяется, таймеры и ретраи
не используются.

Для уже работающего **частного** managed Preview:

```sh
ITLES_E2E_BASE_URL=http://127.0.0.1:3000 npm --prefix frontend run test:e2e
```

В этом режиме новый сервер не запускается. Тесты создают только случайные
`e2e-<UUID>` компании и синтетические данные. В конце отзываются их токены и
пользователи, завершаются их сеансы; строки компаний и показаний остаются,
поскольку API удаления компании отсутствует. Чужие компании и сеансы демо
не удаляются. Для полностью чистой проверки используйте временную БД по умолчанию.
Регистрация и демо должны быть включены. Лимиты защиты остаются включёнными;
частые повторы на общем Preview могут получить 429, это не повод сбрасывать лимиты.

Снимки, видео, trace и HAR не включены: формы показывают одноразовые секреты.
Диагностика падений находится только в git-ignored `.hoplite/artifacts/e2e`;
она может содержать DOM с тестовым секретом и не должна публиковаться без очистки.
Коды и пароли создаются на запуск, не записываются в исходники или отчёт.

Покрытие: веб-регистрация и сохранение кода; повторный вход; сохранённая машина
и неподдерживаемый источник; выдача/активация/отзыв доступа и завершение сеансов;
серверный запрет административных действий; две компании и прямые API/CSV;
настоящий HTTP ingest синтетического пакета с нулём и ручной отметкой сравнения;
замена и отзыв токена, идемпотентный повтор пакета; демо из чистого контекста
и повторный вход; фиксированный сценарий 14–15 сентября 2026; карта, даты, отсутствие
данных, скачивание CSV; имитация отключённого демо и недоступного API;
диагностика HTML 405 и повторный запрос при выключенном демо;
мобильная ширина, клавиатура, меню, Escape и видимый фокус. Chromium-контексты не используют
постоянную agent-browser сессию.

`embedded-auth.e2e.ts` проверяет отдельный контекст: родитель `localhost` и
приложение `127.0.0.1` имеют разные sites. Подменяется только HTML родителя;
приложение и API настоящие, с временной SQLite. Локальное сетевое разрешение
выдаётся тестовому родителю, cookie-политика браузера не меняется.
Тест воспроизводит POST 200 → `/me` 401 в iframe и проверяет ссылку новой вкладки,
отсутствие auth POST из встроенного UI, вход без ключа, reload и выход.
Это не проверка авторизованного HTTPS-шлюза Hoplite.

Проверка нулевого показания перед ручным обновлением использует `expect.soft`,
чтобы после ошибки проверить также обновление, замену и отзыв токена. Такая
ошибка всё равно делает весь тест красным; ожидания не пропускаются.

Это не испытание реальной техники, OEM-файла, точности датчиков, 1С или внешнего
HTTPS-развёртывания. Подмена `/api/auth/options` проверяет текст и состояние UI,
а не фактическую конфигурацию выключенного сервера. Мобильный smoke не заменяет
полный аудит доступности и проверку всех браузеров.
